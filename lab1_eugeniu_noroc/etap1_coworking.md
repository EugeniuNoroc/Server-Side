# Этап 1. Анализ предметной области

## 1. Название приложения

**CoWork Hub** - система управления коворкинг-центром.

## 2. Назначение приложения

Приложение помогает управлять коворкингом: бронировать рабочие места и переговорные комнаты, вести учёт клиентов и их абонементов, контролировать занятость помещений.

## 3. Кто будет пользоваться системой?

- **Клиенты** - бронируют места, покупают абонементы, смотрят свои брони.

- **Администратор** - управляет местами, бронированиями, клиентами и тарифами.

## 4. Основные функции

- Регистрация и вход клиентов.

- Просмотр списка свободных рабочих мест и переговорных.

- Бронирование места на дату и время.

- Отмена бронирования.

- Покупка абонемента (тарифа).

- Просмотр истории своих бронирований.

- Добавление, изменение и удаление мест (администратор).

## 5. Какие данные необходимо хранить?

- Данные клиентов: имя, фамилия, email, телефон.

- Рабочие места: название, тип (рабочее место / переговорная), вместимость, цена за час.

- Бронирования: кто, какое место, дата, время начала и окончания, статус.

- Тарифы и абонементы: название, цена, срок действия.





## 6. Минимум 4 основные сущности

| Сущность | Основные поля |
| - | - |
| **Client** (Клиент) | id, firstName, lastName, email, phone |
| **Workspace** (Рабочее место) | id, name, type, capacity, pricePerHour |
| **Booking** (Бронирование) | id, clientId, workspaceId, date, startTime, endTime, status |
| **Membership** (Абонемент) | id, clientId, tariffName, price, startDate, endDate |


**Связи:**

- Один клиент может иметь много бронирований и абонементов.

- Одно рабочее место может быть забронировано много раз, но в разное время.
